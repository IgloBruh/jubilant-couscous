# depviz — визуализатор графа зависимостей пакетов

## Общее описание

`depviz` — CLI-инструмент для визуализации графа зависимостей пакетов
менеджера пакетов Alpine Linux (`apk`). Готовые менеджеры пакетов и
библиотеки для получения зависимостей не используются.

Практическая работа № 2, вариант 9. Текущее состояние —
**этап 3: основные операции**. Приложение читает параметры из XML-файла,
скачивает индекс репозитория Alpine Linux (`APKINDEX.tar.gz`) или читает
файл тестового репозитория и строит граф зависимостей заданного пакета
с учётом транзитивности, максимальной глубины, фильтра и циклов.

Реализация на Python 3.10+ без сторонних зависимостей: для загрузки и
распаковки используются только модули стандартной библиотеки
(`urllib`, `tarfile`).

### Как извлекаются зависимости

Репозиторий Alpine содержит файл `APKINDEX.tar.gz`, внутри которого
лежит текстовый `APKINDEX`. Он состоит из записей, разделённых пустыми
строками; каждая строка записи имеет вид `X:значение`:

- `P` — имя пакета, `V` — версия;
- `D` — зависимости через пробел;
- `p` — что пакет предоставляет (`so:libz.so.1`, `cmd:sh`, `/bin/sh`);
- `k` — приоритет поставщика.

Зависимости из `D` обрабатываются так:

- ограничения версии (`>=`, `<`, `=`, `~`) отбрасываются;
- конфликты (`!пакет`) не считаются зависимостями;
- виртуальные зависимости (`so:…`, `cmd:…`, `/bin/sh`) разрешаются в
  конкретный пакет через поле `p`; при нескольких поставщиках
  выбирается пакет с наибольшим приоритетом `k`, затем по имени;
- требования, которые удовлетворяет один и тот же пакет, объединяются.

### Построение графа

Граф строится обходом в глубину (DFS) **без рекурсии**: вместо стека
вызовов используется явный стек, каждый элемент которого — пакет, его
глубина и итератор по ещё не просмотренным зависимостям. Поэтому длинные
цепочки зависимостей не упираются в предел рекурсии Python (в тестах
проверена цепочка из 5000 пакетов).

- **Глубина.** Корневой пакет имеет глубину 0, его прямые зависимости —
  1 и т. д. Пакеты на глубине `max_depth` попадают в граф, но их
  зависимости не раскрываются; такие пакеты перечисляются в отчёте.
  Если пакет сначала найден по длинному пути, а потом по более
  короткому, он раскрывается заново, так что результат не зависит от
  порядка обхода.
- **Фильтр.** Пакеты, имя которых содержит `filter_substring` (с учётом
  регистра), исключаются из анализа вместе со всеми зависимостями,
  достижимыми только через них. Корневой пакет не фильтруется.
- **Циклы.** Обход хранит множество пакетов на текущем пути от корня.
  Ребро в пакет из этого множества замыкает цикл: оно сохраняется в
  графе и выводится в отчёте, но повторно пакет не раскрывается, поэтому
  обход всегда завершается. Повторное попадание в уже полностью
  обработанный пакет (как в «ромбе» A→B→D, A→C→D) циклом не считается.
- **Отсутствующие пакеты.** Зависимость, которой нет в репозитории,
  остаётся листом графа и указывается в отчёте.

### Тестовый режим

При `test_repo_mode=true` вместо URL указывается путь к файлу описания
графа репозитория. Каждая непустая строка имеет вид `A: B C` (пакет `A`
зависит от `B` и `C`), имена пакетов — большие латинские буквы.
Пакет без зависимостей записывается как `D:`.

Параметр `ascii_tree` уже читается и проверяется, но используется на
этапе 5.

## Структура репозитория

```
config.xml            конфигурация по умолчанию
examples/             примеры конфигураций и тестовый репозиторий
  test_mode.xml       конфигурация тестового режима
  test_repo.txt       файл описания тестового репозитория
  repos/              тестовые репозитории для разных случаев
  cases/              конфигурации для демонстрации этих случаев
  errors/             конфигурации с ошибками для демонстрации
src/depviz/           исходный код
  cli.py              интерфейс командной строки
  config.py           загрузка и проверка конфигурации
  apkindex.py         разбор APKINDEX и поиск прямых зависимостей
  repository.py       загрузка индекса по URL и тестового репозитория
  graph.py            построение графа зависимостей (DFS без рекурсии)
  render.py           текстовый отчёт о графе
tests/                модульные тесты (unittest)
run.sh, run.bat       скрипты запуска
Makefile              цели run и test
```

## Настройки

Конфигурация задаётся XML-файлом с корневым элементом `<config>`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <package_name>busybox</package_name>
    <repository>https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64</repository>
    <test_repo_mode>false</test_repo_mode>
    <ascii_tree>true</ascii_tree>
    <max_depth>3</max_depth>
    <filter_substring>doc</filter_substring>
</config>
```

| Параметр           | Обяз. | Описание и допустимые значения |
|--------------------|-------|--------------------------------|
| `package_name`     | да    | Имя анализируемого пакета: латинские буквы, цифры, `. _ + -`; начинается с буквы или цифры |
| `repository`       | да    | URL каталога репозитория (`http`/`https`; к нему добавляется `/APKINDEX.tar.gz`) или URL самого архива; в тестовом режиме — путь к файлу тестового репозитория (относительный путь отсчитывается от каталога конфигурации) |
| `test_repo_mode`   | да    | Режим работы с тестовым репозиторием: `true/false`, `yes/no`, `on/off`, `1/0` |
| `ascii_tree`       | да    | Режим вывода зависимостей в виде ASCII-дерева: те же логические значения |
| `max_depth`        | да    | Максимальная глубина анализа — целое число от 1 до 100 |
| `filter_substring` | нет   | Подстрока для фильтрации пакетов, без пробелов; по умолчанию пустая (фильтр выключен) |

### Обработка ошибок

Коды завершения:

| Код | Значение |
|-----|----------|
| 0   | успешно |
| 1   | ошибка конфигурации |
| 2   | ошибка репозитория: сеть, HTTP-ошибка, повреждённый архив, неверный формат тестового репозитория |
| 3   | пакет не найден в репозитории |

Конфигурация проверяется целиком, и приложение сообщает **все**
найденные в ней ошибки сразу. Обрабатываются:

- отсутствующий или нечитаемый файл конфигурации;
- синтаксически некорректный XML;
- неверный корневой элемент;
- неизвестные, повторяющиеся и составные (с вложенными тегами) параметры;
- отсутствие обязательных параметров;
- некорректные значения каждого параметра (см. таблицу выше);
- некорректный URL или отсутствующий файл тестового репозитория.

## Функции

Модуль `depviz.config`:

- `load_config(path)` — загрузить и проверить конфигурацию, вернуть
  объект `Config` или выбросить `ConfigError` со списком ошибок;
- `read_root(path)` — прочитать XML и вернуть корневой элемент;
- `collect_raw_values(root)` — собрать текстовые значения параметров
  и ошибки структуры;
- `parse_fields(raw_values)` — разобрать значения всех параметров;
- `parse_package_name`, `parse_repository`, `parse_bool`,
  `parse_max_depth`, `parse_filter_substring` — проверка отдельных
  параметров;
- `check_repository(repository, test_mode, base_dir)` — проверка
  репозитория с учётом режима работы.

Модуль `depviz.apkindex`:

- `parse_index(text)` — разобрать текст APKINDEX, вернуть `ApkIndex`;
- `split_records(text)`, `parse_record(lines)` — разбиение на записи и
  разбор одной записи в `Package`;
- `strip_constraint(token)` — отбросить ограничение версии;
- `ApkIndex.get(name)` — пакет по имени (иначе `PackageNotFoundError`);
- `ApkIndex.resolve(requirement)` — имя пакета, удовлетворяющего
  требованию;
- `ApkIndex.direct_dependencies(name)` — список прямых зависимостей
  (`Dependency`: имя пакета, исходные требования, найден ли пакет).

Модуль `depviz.repository`:

- `index_url(url)` — URL архива индекса;
- `download(url)` — скачать данные (ошибки → `RepositoryError`);
- `extract_index(archive)` — извлечь текст `APKINDEX` из архива;
- `load_remote_index(url)` — скачать и разобрать индекс;
- `parse_test_line`, `parse_test_repo`, `load_test_repo` — разбор
  файла тестового репозитория;
- `open_repository(config)` — загрузить индекс согласно конфигурации.

Модуль `depviz.graph`:

- `DependencyGraph` — граф: `edges` (пакет → список зависимостей),
  `cycles`, `truncated`, `filtered`, `missing`; методы `nodes`,
  `edge_count()`, `add_cycle(source, target)`;
- `GraphBuilder(index, max_depth, filter_substring)` — построитель
  графа; `build(root)` выполняет нерекурсивный DFS;
- `build_graph(index, config)` — построить граф по конфигурации.

Модуль `depviz.render`:

- `format_graph(graph, config)` — текстовый отчёт о графе;
- `format_edges(graph)`, `format_section(title, items)` — части отчёта.

Модуль `depviz.cli`:

- `build_parser()` — парсер аргументов командной строки;
- `report_error(title, messages)` — вывод ошибок в stderr;
- `main(argv=None)` — запуск приложения, возвращает код завершения.

## Сборка и запуск

Сборка не требуется, нужен только Python 3.10+. Для работы с реальным
репозиторием нужен доступ в интернет.

Запуск с конфигурацией по умолчанию (`config.xml`):

```bash
./run.sh
```

Windows:

```bat
run.bat
```

Указать другой файл конфигурации:

```bash
./run.sh -c examples/test_mode.xml
```

Без скриптов:

```bash
PYTHONPATH=src python -m depviz -c config.xml
```

### Тесты

```bash
python -m unittest discover -s tests -t . -v
```

или `make test`. Тесты не обращаются к сети: загрузка индекса
подменяется через `unittest.mock`.

### Тестовый репозиторий

Демонстрационные случаи лежат в `examples/cases/` (репозитории — в
`examples/repos/`). Запуск всех сразу:

```bash
for f in examples/cases/*.xml; do ./run.sh -c "$f"; done
```

| Конфигурация          | Репозиторий                                   | Что показывает |
|-----------------------|-----------------------------------------------|----------------|
| `diamond.xml`         | `A: B C`, `B: D`, `C: D`, `D:`                | общая зависимость, не цикл |
| `cycle.xml`           | `A: B`, `B: C`, `C: A D`, `D:`                | цикл A→B→C→A |
| `self_loop.xml`       | `A: A B`, `B: B`                              | пакет зависит сам от себя |
| `complex.xml`         | 8 пакетов, 12 связей                          | несколько циклов |
| `depth_limit.xml`     | цепочка A→B→C→D→E→F, глубина 3                | ограничение глубины |
| `depth_shortcut.xml`  | `A: B D`, `B: C`, `C: D`, `D: E`, глубина 3   | короткий путь найден позже |
| `filter.xml`          | `APP`, `LIBA`, `LIBB`, `TESTKIT`, … фильтр `TEST` | фильтрация пакетов |
| `missing.xml`         | `A: B X`, `B: Y`                              | отсутствующие пакеты |

Цикл:

```
$ ./run.sh -c examples/cases/cycle.xml
Граф зависимостей пакета A
Максимальная глубина: 10; фильтр: нет
Пакетов: 4, связей: 4
Связи:
  A -> B
  B -> C
  C -> A, D
  D
Циклические зависимости (1):
  C -> A
```

Ограничение глубины:

```
$ ./run.sh -c examples/cases/depth_limit.xml
Граф зависимостей пакета A
Максимальная глубина: 3; фильтр: нет
Пакетов: 4, связей: 3
Связи:
  A -> B
  B -> C
  C -> D
  D
Не раскрыты из-за ограничения глубины (1):
  D
```

Короткий путь, найденный позже: D сначала встречается на глубине 3

раскрывается, и в граф попадает E:

```
  B -> C
  C -> D
  D -> E
  E
```

### Ошибки

Ошибки репозитория и отсутствующий пакет:

```
$ ./run.sh -c examples/errors/bad_test_repo.xml
Ошибка репозитория:
  - строка 2: имя пакета 'b' должно состоять из больших латинских букв

$ ./run.sh -c examples/errors/unknown_package.xml
Ошибка:
  - пакет 'Z' не найден в репозитории
```

При недоступном сервере или неверном URL выводится, например,
`сервер вернул ошибку 404 для https://…/APKINDEX.tar.gz`.

Ошибки во всех параметрах конфигурации:

```
$ ./run.sh -c examples/errors/bad_values.xml
Ошибка конфигурации:
  - package_name: недопустимое имя пакета: '-bad name'
  - repository: адрес репозитория не может быть пустым
  - test_repo_mode: ожидалось логическое значение (0, 1, false, no, off, on, true, yes), получено 'maybe'
  - ascii_tree: ожидалось логическое значение (0, 1, false, no, off, on, true, yes), получено '2'
  - max_depth: ожидалось целое число, получено 'zero'
  - filter_substring: подстрока не должна содержать пробельных символов: 'a b'
```

Ошибки структуры:

```
$ ./run.sh -c examples/errors/missing_and_unknown.xml
Ошибка конфигурации:
  - параметр <package_name> задан более одного раза
  - неизвестный параметр <colour>
  - параметр <max_depth> не должен иметь вложенных тегов
  - отсутствует обязательный параметр <repository>
  - отсутствует обязательный параметр <test_repo_mode>
  - отсутствует обязательный параметр <ascii_tree>
  - отсутствует обязательный параметр <max_depth>
```

Другие примеры ошибок: `examples/errors/malformed.xml` (некорректный XML),
`wrong_root.xml` (неверный корень), `out_of_range.xml` (глубина вне
диапазона), `missing_test_repo.xml` (нет файла тестового репозитория).
